TRACK ARROW CALCULATION:
────────────────────────
Track heading → Arrow character (8 directions)

  337.5° - 22.5°   →  ↑   North
   22.5° - 67.5°   →  ↗   Northeast
   67.5° - 112.5°  →  →   East
  112.5° - 157.5°  →  ↘   Southeast
  157.5° - 202.5°  →  ↓   South
  202.5° - 247.5°  →  ↙   Southwest
  247.5° - 292.5°  →  ←   West
  292.5° - 337.5°  →  ↖   Northwest

Python implementation:
```python
def get_direction_arrow(track: float) -> str:
    track = track % 360  # Normalize to 0-360
    if 337.5 <= track or track < 22.5:
        return "↑"   # N
    elif 22.5 <= track < 67.5:
        return "↗"   # NE
    elif 67.5 <= track < 112.5:
        return "→"   # E
    elif 112.5 <= track < 157.5:
        return "↘"   # SE
    elif 157.5 <= track < 202.5:
        return "↓"   # S
    elif 202.5 <= track < 247.5:
        return "↙"   # SW
    elif 247.5 <= track < 292.5:
        return "←"   # W
    else:  # 292.5 <= track < 337.5
        return "↖"   # NW
```


RADAR VIEW (right panel when split):
─────────────────────────────────────
Polar coordinate display centered on ownship:

Components:
1. Header: "Range: XX nm    Track: XXX°"
2. Range rings: Two concentric circles
   - Inner ring: 50% of max range (dotted: ·)
   - Outer ring: 100% of max range (box chars: ╔═╗║╚╝)
3. Ownship: ⊕ at center with track arrow (↗)
4. Traffic targets plotted by bearing and distance:
   - Format: →CALL
   - Below: ±ALT  DIST
   - Arrow shows target's track direction
   - Abbreviated callsign (3-4 chars)
   - Relative altitude (±feet or = for same)
   - Distance in nm

Target positioning:
- X = center_x + (distance / max_range) × radius × sin(bearing)
- Y = center_y - (distance / max_range) × radius × cos(bearing)
- Bearing in radians: bearing × π / 180

Legend at bottom:
- ⊕ = Ownship (center, with track arrow)
- · = Range rings
- →CALL = Target with track arrow
- ±XXXX = Relative altitude
- X.X = Distance in nm

Color coding by altitude separation:
* Red: |separation| < 500ft (collision warning)
* Yellow: 500 ≤ |separation| < 1000ft (caution)
* Green: |separation| ≥ 1000ft (safe)
* White: Unknown altitude

Traffic summary:
- "Traffic in range: X"
- "Closest: CALLSIGN (X.Xnm DIR)"

RELATIVE ALTITUDE DISPLAY:
──────────────────────────
Format in traffic table:
- Same altitude: "5,000ft ="
- Above ownship: "6,500ft +1500"
- Below ownship: "3,500ft -1500"

Calculation: target_altitude - ownship_altitude

Color coding (future):
- Red: |difference| < 500ft (collision risk)
- Yellow: 500 ≤ |difference| < 1000ft (caution)
- Green: |difference| ≥ 1000ft (safe)


TRAFFIC SORTING:
────────────────
Primary sort: Distance (ascending) - closest aircraft first
Display limit: 20 rows maximum
Pruning: Remove contacts older than TTL (default 60 seconds)


DATA UPDATE CYCLE:
──────────────────
Refresh interval: 0.5 seconds (2 Hz)

On each refresh:
1. Prune stale contacts (age > TTL)
2. Recalculate relative altitudes (if ownship altitude available)
3. Refresh TrafficTable widget
4. Refresh RadarView widget (if visible)
5. Update StatusBar (traffic count, feedback flags)


VISUAL FEEDBACK TIMERS:
───────────────────────
Split toggle feedback: 2 seconds
Range change feedback: 2 seconds

Implementation: Timer set on action, clears flag after timeout

RESPONSIVE BEHAVIOR:

THREADING MODEL:
────────────────
Main thread: Textual app event loop
Background thread: UDP receiver (daemon)
Communication: call_from_thread() for thread-safe updates

Receiver thread:
1. Binds to UDP port 4000
2. Receives GDL90 packets
3. Processes with decoder
4. Calls data_received() on first packet
5. Updates demo data (until decoder properly integrated)
